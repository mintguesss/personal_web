MingLu on KNEO Pi

明路的開發板版本：原本由筆電負責辨識，改由 Kneron KNEO Pi（KL730，2GB 記憶體）負責。手機只當眼睛和喇叭，三個模型全在板上離線執行，影像和聲音不送到第三方雲端。

角色：KNEO Pi 版開發（電腦版：kobocawaee/minglu）技術主軸：邊緣裝置推論 · 2GB 記憶體下的模型取捨平台：Android 手機（Chrome）+ Kneron KNEO Pi
GitHub

重點

+

一題 9 分鐘 → 22 秒

Gemma 改用 LiteRT-LM，不用 llama.cpp

llama.cpp 的模型比記憶體大，每生成一個字都要從 microSD 重讀；LiteRT-LM 版可以常駐記憶體。

+

周遭描述約 0.5 秒

YOLOv8n 轉成 NEF，在 KL730 NPU 上跑

模型切在偵測頭最後一層卷積，DFL 解碼與 NMS 在 CPU 上用 numpy 做；開機後第一次約 7 秒。

+

三個模型塞進 2GB

YOLOv8n、Whisper base、Gemma 4 E2B 同時常駐

關閉桌面環境省約 900MB，另開 4GB swap；Whisper 改成常駐服務，避免每次重啟把 Gemma 擠出記憶體。

+

安裝後全程離線

影像和聲音不送到第三方雲端

安裝時要下載約 2.7GB 的模型，之後板子可以完全離線使用。

↑ 點任一張卡片看它怎麼做到的

為什麼做這個

明路原本是電腦版：筆電負責辨識，手機負責拍照和唸出結果。這個版本拿掉筆電，只用手機加一塊 Kneron KNEO Pi 開發板就能使用。

難處在板子本身：只有 2GB 記憶體和 4 核 1.1GHz 的 Cortex-A55，NPU 只能加速 YOLO 這類 CNN，不能跑 Gemma。電腦版用的 Gemma 3 4B、Whisper large-v3-turbo、EasyOCR 都放不進來，每個模型都得重新選、重新量。

這個版本沒有過馬路和紅綠燈判斷，問到時會直接說不提供。

功能總覽

周遭、室內+說出前方有什麼、在哪個方位、多近

YOLOv8n 在 KL730 NPU 上偵測，再組成繁中句子，約 0.5 秒；偵測不到才交給 Gemma。

物品+說出拿在鏡頭前的東西是什麼

交給 Gemma 4 E2B，約 25~36 秒。YOLOv8n 會把耳機認成滑鼠，所以物品不用它認。

讀字+照原樣唸出畫面上的文字

由 Gemma 4 E2B 讀，約 40~48 秒。

語音指令與提問+切換模式、調語速字體，或直接問「這是什麼」

Whisper base 辨識語音指令約 6 秒；提問會先唸「聽到了，正在看」，可以追問，整題約 30~40 秒。

LCD 狀態顯示+1602 I2C LCD 顯示板子 IP 和目前狀態

第一行是手機要連的 IP，熱點換 IP 會自動更新；第二行顯示載入、聆聽、思考，或這次偵測到的東西。

關鍵技術決策

Gemma 用 LiteRT-LM，不用 llama.cpp

llama.cpp 的模型比記憶體大，每生成一個字都要從 microSD 重讀，一題約 9 分鐘。LiteRT-LM 版可以常駐，一題約 22 秒。

系統架構

手機（Chrome：相機、麥克風、TTS 唸出結果）
↓ HTTPS 傳照片、錄音，回傳文字
KNEO Pi（app/server.py）
├─ YOLOv8n → KL730 NPU（周遭、室內）
├─ Whisper base → whisper-server（常駐）
├─ Gemma 4 E2B → LiteRT-LM（常駐，CPU）
└─ I2C LCD：顯示 IP 和狀態
